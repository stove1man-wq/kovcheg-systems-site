# Архитектура корпоративного сайта KOVCHEG SYSTEMS

> Статус: первая рабочая архитектурная версия. Технологический стек намеренно не фиксируется.

## 1. Граница проекта

Сайт размещается в корне репозитория (GitHub Pages публикует `main`, домен задан файлом `CNAME`). Старая версия сайта (проверочная страница привязки домена и страницы проектов) удалена 8 ноября 2026; восстановить её можно из истории git.

## 2. Текущий формат

Первый этап — самостоятельный статический сайт на HTML, CSS и небольшом количестве JavaScript без обязательной сборки и внешних runtime-зависимостей.

Причины:
- быстрый просмотр локально в браузере;
- минимальная инфраструктура;
- отсутствие привязки к конкретному фреймворку до проверки требований;
- простая миграция к компонентной архитектуре, если она понадобится.

Это не окончательное решение о будущем стеке.

## 4. Информационная архитектура

Главная страница строится как последовательный рассказ о компании:

1. **Home / Главная** — позиционирование, слоган, краткое обещание.
2. **AI Systems / Системы ИИ** — интеллектуальные агенты, автономность, локальная работа и интеграции.
3. **Digital Ecosystems / Цифровые экосистемы** — связность продуктов, сервисов и пользовательских сценариев.
4. **Robotics / Робототехника** — соединение цифрового интеллекта с физическими системами.
5. **Projects / Проекты** — конкретные разработки и демонстрации.
6. **Research & Innovation / Исследования** — направления экспериментов и технологического развития.
7. **About / О компании** — миссия, принципы и подход к разработке.
8. **Contacts / Контакты** — понятный канал для деловых обращений.

На первом этапе это одна адаптивная страница с якорной навигацией. Отдельные страницы можно выделить позже, когда появятся подтверждённые материалы и контент.

## 5. Визуальные правила интерфейса

- Органический футуризм без перегруженных sci-fi эффектов.
- Глубокая графитовая основа, нефритовые и медные акценты, жемчужные текстовые поверхности.
- Изображения используются как крупные смысловые композиции, а не как декоративные миниатюры.
- Контраст, масштаб текста и свободное пространство важнее декоративных эффектов.
- Анимации короткие и ненавязчивые; при `prefers-reduced-motion: reduce` они отключаются.
- Навигация должна работать с клавиатуры и на сенсорных устройствах.
- Изображения получают осмысленный alt-текст; декоративные изображения — пустой alt.

## 6. Принципы реализации

- Семантические HTML-элементы и логичная иерархия заголовков.
- Адаптивная сетка без горизонтальной прокрутки.
- CSS-переменные для палитры и размеров.
- JavaScript только для функций, которые нельзя разумно реализовать CSS: мобильное меню, плавное появление контента, текущий год.
- Не добавлять фиктивную отправку формы. Контактный сценарий должен быть подключён только после определения реального адреса или сервиса.
- Не подключать аналитику, внешние шрифты и сторонние библиотеки без необходимости.
- Не считать визуальные эффекты доказательством функциональности.

## 7. Контроль качества

Перед публикацией проверить:
- пути ко всем изображениям и ресурсам;
- работу навигации и мобильного меню;
- отсутствие ошибок JavaScript в консоли;
- доступность основных элементов с клавиатуры;
- контраст и читаемость на мобильной ширине;
- поведение при уменьшении анимации;
- метаданные страницы и Open Graph;
- фавикон и картинка для превью ссылки (Open Graph) открываются по абсолютным адресам.

## 8. Открытые решения

Не фиксируются до получения достаточных оснований:
- окончательный шрифт;
- окончательный состав языковых версий;
- технологический стек для возможного расширения;
- CRM, почтовый сервис и обработчик контактной формы;
- аналитика и SEO-инструменты.
